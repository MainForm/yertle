# PMW3901 acquisition and wire contract

Pins: SPI1 PA5 CLK, PA6 MIS, PA7 MOS; GPIO PA4 CS (idle high), PA0 RST
(idle high); PC7 MOT is optional and configured as input, no EXTI handler.
Module 3V3 and common GND. Leave VRE disconnected. Verify the actual module
power circuit before wiring. PA5 shares the Nucleo user LED; PB6 is IMU SCL.
SPI1 is mode 3, MSB first, 1 MHz at APB2 64 MHz. NO DMA: channels 2/3
are already USART3 motor DMA. No IRQ masking during optical transactions.

Initialization is a stepwise state machine: at most one SPI operation per
20ms service call. Power/reset waits and register-table waits span calls.
Expect roughly two seconds until READY. Each SPI transaction is bounded;
errors publish invalid status and retry initialization after one second.
Product ID is rechecked each second. No missing-sensor assumption of zero flow.
First burst after initialization is discarded for displacement/interval use.
Low SQUAL is retained as raw quality data, never certified as reliable flow.
No metres, velocity conversion, axis remapping, or policy observation change.

Initialization/timing reference: Bitcraze official PMW3901 driver,
https://github.com/bitcraze/crazyflie-firmware/blob/master/src/drivers/src/pmw3901.c
The adapted initialization table retains the upstream LGPL-3.0-or-later
copyright/license notice. Chip data: PixArt PMW3901MB product datasheet.

## GET_SENSOR_FEEDBACK response extension (schema 1, type 0x92)

An optional 44-byte payload is sent BEFORE the existing three motor chunks
and IMU response. Existing required-response completion rules are unchanged.
All integers little-endian except shutter: raw burst bytes 10/11 are high/low.

Offsets: 0 request_sequence u16; 2 schema u8=1; 3 flags u8 (bit0 valid,
bit1 ready, bit2 interval valid); 4 parent motor sample u32; 8 parent uptime_ms
u32; 12 optical sequence u32; 16 optical acquisition-start uptime_ms u32;
20 interval_ms u32; 24 exact 12-byte motion burst; 36 total errors u32;
40 reset epoch u16; 42 driver state u8; 43 last_error u8 (0 none,1 SPI,2 ID).
Sequence advances only on successful burst. Invalid/status-only frames can
repeat a sequence; do not accumulate dx/dy twice. Age uses the optical time,
not host response time or parent motor time. After sensor failure/restart,
the first displacement interval is invalid. Missing intermediate optical
sequence numbers mean lost intervals, not displacement recoverable from dt.
Full response adds about 55 wire bytes, ~0.55ms at 1Mbaud 8N1, ~2.75% at50Hz.
This is a wire-time estimate, not measured control-loop performance.

## Offline verification and hardware follow-up

Windows: cmake -S tests/diagnostics -B build/pmw-diagnostic-tests -A x64;
cmake --build build/pmw-diagnostic-tests --config Release;
ctest --test-dir build/pmw-diagnostic-tests -C Release --output-on-failure.
PMW tests exercise init call bounds, first invalid interval, missing sensor,
SPI failure, retry epoch and the actual 44-byte firmware serializer.
The adapted register table license texts are in LICENSES/PMW3901-*.

After flashing, use F3 only (no arming needed). Allow initialization to finish;
check READY, increasing optical sequence, plausible interval and quality.
Move the sensor over a textured surface in each physical direction, recording
axis/sign rather than assuming robot frame alignment. Then test no texture,
unplug/reconnect and errors without losing other sensors. Measure actual
sensor/control intervals and UART errors under normal motor load before
claiming 50Hz hardware performance. No physical test has been performed here.
